06 Control-flow architecture

Boot, product, UDS, fault, and OTA state machines. Events come from queues, timers, and system-style blocking calls — not busy loops.

1. Boot sequence

RESET
  → early init (clocks, WDT start)
  → read reset reason / last fault from NVS
  → BSP pin map
  → HAL init (selected instances)
  → middleware (queues, logger)
  → protocol init
  → service init
  → create product task subset
  → product SM = RUN
  → scheduler start (app_main returns)

2. Product run SM

INIT
  → RUN                 (all critical inits OK)
  → DEGRADED            (optional function lost, e.g. BLE down)
  → FAULT               (critical path lost, e.g. CAN bus-off)
  → RECOVERY            (driver reinit, session abort)
  → RUN                 (recovered)
  → SAFE                (recovery budget exceeded)
SAFE: CAN TX silent, outputs default, BLE advertise "SAFE", WDT still kicked if possible

3. Fault manager (Safety agent)

NORMAL
  --detect--> FAULT_DETECTED
  --confirm--> DEGRADED          (non-critical)
  --confirm--> RECOVERY          (critical, restartable)
  --ok--> NORMAL
  --fail budget--> SAFE_STATE

Examples: CAN timeout, sensor fail, battery over-temp, low voltage, comms loss, task heartbeat miss.

4. UDS session SM

DEFAULT (0x01)
  --0x10 0x03 + OK--> EXTENDED
  --0x10 0x02 + security--> PROGRAMMING
EXTENDED / PROGRAMMING
  --S3 timeout / 0x10 0x01--> DEFAULT
  --0x11 reset--> ECU_RESET --> boot
  --0x27 fail count--> LOCKOUT (timer)

Tester Present 0x3E resets S3. Server and client are separate SMs sharing ISO-TP.

5. ISO-TP transfer SM

IDLE
  --SF--> RX_DONE / TX_DONE
  --FF--> RX_WAIT_FC or TX_WAIT_FC
  --FC CTS--> TX_CF / RX_CF
  --N_TIMEOUT / overflow--> IDLE + error
  --last CF--> DONE --> IDLE

6. BLE connection SM

ADV
  --connect--> CONNECTED_OPEN
  --paired/bonded--> CONNECTED_SECURE   (prototype)
  --timeout / link loss--> RECONNECT_WAIT
  --budget--> ADV
  --auth fail--> ADV + rate limit

7. OTA / bootloader SM

BOOT_SELECT
  → DOWNLOAD
  → TRANSFER
  → VERIFY (CRC/hash + metadata)
  → COMMIT (swap mark)
  → BOOT
VERIFY fail or power loss in TRANSFER
  → DISCARD inactive slot
  → remain on current image

8. CAN driver control

STOPPED → STARTED
STARTED --error warning--> ERROR_ACTIVE
ERROR_ACTIVE --bus-off--> BUS_OFF
BUS_OFF --recover policy / timer--> RECOVERING → STARTED
RECOVERING --fail--> FAULT (fault manager)
