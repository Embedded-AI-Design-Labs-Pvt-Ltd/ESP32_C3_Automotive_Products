11 Automotive CAN scenarios

Automotive Architect view. Realistic jobs, SIM / PROTO IDs — not OEM production databases.

All CAN IDs below are simulated for this prototype. Do not use them on a public road vehicle. Payload layouts are teaching models.

Reusable CAN database structure

typedef struct {
  uint32_t id;
  uint8_t  ide;
  uint8_t  dlc;
  uint16_t cycle_ms;     /* 0 = event */
  uint16_t timeout_ms;
  uint8_t  dir;          /* TX / RX from this node's view */
  const char *name;
  const ae_signal_t *signals;
  uint8_t signal_count;
} ae_can_msg_def_t;

8. HIL / EOL

HIL uses the same IDs as stimulus. EOL sequence example: power sim → 0x200 ready → 0x10 extended → 0x22 F190 VIN → 0x31 routine self-test → pass/fail.

9. Example scenario: tester reads VIN

  1. Tester sends ISO-TP SF: 0x7E0 03 22 F1 90
  2. ECU replies 0x7E8 first frame if VIN > 5 data bytes
  3. Tester FC CTS; ECU CF completes
  4. Timeout any step → fail; unexpected SID → NRC 0x11

10. Example scenario: BMS over-temp

  1. 0x302 max temp > 55 °C (SIM threshold)
  2. DTC P1A02 confirm after 3 samples
  3. 0x303 discharge limit → 0
  4. VCU 0x201 torque req ignored / forced 0 in simulator
  5. BLE battery characteristic notifies over-temp flag
