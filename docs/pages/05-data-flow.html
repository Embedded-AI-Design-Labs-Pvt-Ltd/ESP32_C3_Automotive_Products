05 Data-flow architecture

How bytes move. Ownership transfers at each queue. No shared frame buffers across tasks without a pool checkout.

1. Canonical CAN frame object

ae_can_frame_t {
  uint32_t id;          /* 11 or 29 bit */
  uint8_t  ide;         /* 0 standard, 1 extended */
  uint8_t  rtr;
  uint8_t  dlc;
  uint8_t  data[8];
  uint32_t timestamp_us;
  uint8_t  flags;       /* overflow, error, injected */
}

Allocated from a static pool. ISR copies into a pool slot or a queue item. Consumer returns the slot.

9. Ownership rules

  • Producer fills a pool slot, sends pointer or value copy (frames are 16–24 bytes; copy is preferred).
  • ISO-TP owns the reassembly buffer until UDS copies out the PDU.
  • BLE characteristic writes are copied into a command struct before leaving the stack callback.
  • Config blobs are double-buffered; readers see a const snapshot.
